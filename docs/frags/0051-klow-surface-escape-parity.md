# klow surface program + string-escape parity

`klow` — the koru-spelled reifier (rows + src → ast.json) — exists
as a validated surface draft at `_scratch/klow.k` (~165 tors,
generated by `_scratch/_genklow*.py` builders).  On the corpus:
**40/44 leaf files produce a document deep-equal (parsed-JSON) to
`korufe --reify`**; the four self-parse files (900_kemit,
901_klex, 902_ksexp, 903_kast) die with `0xC00000FD` — the named
trampolined-invokes axis from 0047, not a semantic gap.  klow.k
parses under both `korufe` and the authority `koruc -c`
(pun-or-label args, `_` discards, no redundant `x: x`).

## What klow had to learn — escape parity

korufe's string lexer kept `\` raw; upstream zig koru honors `\"`,
`\\`, `\n`, `\t`, `\r` (unknown escapes keep both bytes).  That
divergence was fatal for a program whose whole job is emitting
JSON text.  Fixed across the lane:

- `korufe/lex.c` — `\x` skips inside string literals (no
  interpolation inside escapes either)
- `korufe/parse.c` — `unesc` decodes the upstream set
- `korufe/lower.c` — `bput_sxstr` escapes `"`/`\` on `(str …)`
  wire emit (both sx_lit and jval_sx)
- `krun/sx.c`, `krun/wire.c` — the reader decodes the same set
- `krun/main.c` — `print_val` escapes strings on result print
- `ISAR.kAstToArgEnd` — new `bs` arm: inside a string, `\` skips
  the next byte so `\"` can't toggle `ins`; fixtures regenerated

So koru source can now spell a real quote inside a literal
(`"\""`), which is what a JSON-emitting program needs; span bytes
still go out as `\u00xx` escapes inside those literals — safe,
JSON-equal to korufe's raw output, and byte-agnostic for UTF-8.

## Design facts that fell out

- **Rows cross as a flat int array** — six cells per row
  (`k s a b c d`), the text→array projection is declared data in
  the check harness.  Wire `(cell …)` literals can't carry
  computed fields, so records were never an option.
- **`impl_of` shape**: `[name]` — a one-element array of the
  declared name — not the segments object.
- **`when` + OOB index is refusal**, `&&`/`||` short-circuit —
  guards must order bounds checks first.
- Fuel in `cases.json` must be a JSON *number*; a quoted
  `"99999999"` silently falls back to 64 (a real trap —
  `lower.c` only accepts numeric fuel).

## Refusal parity

`(bad …)` rows, dangling `rbind` at EOF, and out-of-context rows
all refuse in klow exactly as `--reify` refuses.

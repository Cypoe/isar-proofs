ISAR — The Invariant Machine

A complete visual intro to the machine as IOB → SAR → IRAS: from bare pairing, to adjacency and rewrite, to the invariant layer that makes equal things equal across encodings, translations, diffs, and compiled forms.

Why this machine matters

The point is not to invent a new representation. The point is that the invariant layer is already there whenever a system is closed under self-application: different surfaces, encodings, and execution paths factor through the same operational identity. This machine makes that visible and testable.

IOB

Identity, operation, body: something exists, can pair, and can point. This is the smallest structural seed.

Existence
A thing can be referred to.
Pairing
Two things can be related without yet assigning meaning.
Self-description
The system can represent its own relations.

SAR

Once pairing exists, three roles are unavoidable: state, adjacency, and rewrite.

S — State
What can be observed or rendered.
A — Adjacency
How parts are connected.
R — Rewrite
How one description is reduced to another.

IRAS

Add the invariant quotient and the machine closes: equal things have one operational identity.

I — Invariant
What survives every admissible rewrite.
Factoring
Every admissible encoding translates by factoring through the same invariant layer.
Machine
Storage, diff, compilation, translation, and compute become one story.

What is being claimed

decode_utf8(encode_utf8(x)) = x

translate(A → B, x) = view_B(Invariant(decode_A(x)))
nf(program₁) = nf(program₂) ⇒ [program₁] = [program₂]

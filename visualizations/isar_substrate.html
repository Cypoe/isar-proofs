What Survives Translation

Notice this first: a file can be zipped, renamed, or moved without becoming a different file. Follow that one observation through seven settings and you arrive, without ever inventing anything, at a single quotient structure that every one of them turns out to share.

Why this exists

This did not start as a theory of computation, or of physics, or of anything with a capital letter. It started as a much smaller and more practical problem: where do you put an idea so it doesn't get lost, and what happens to that idea once it's stored somewhere?

The first surprise was ordinary and easy to miss. Every time an idea got saved — as a file, a message, a row in a database, a string of bytes — something about it changed, and something about it didn't. The file size changed. The byte layout changed. The character encoding changed. But if you decoded it back, you got the same idea out. That gap between what changed and what didn't is not a curiosity. It is the entire subject of everything that follows.

The second surprise was that this gap already had a name in a field nobody thinks of as exotic: unit conversion. "5 kilometers" and "5000 meters" are not two different distances — they are two labels for one invariant quantity. Once that was visible, it became impossible to unsee the same shape everywhere else: in text encodings, in compiler dialects, in rewrite systems, in database schemas, in self-referential programs. Each one turned out to be the same question asked in a different costume — what is the object, and what is merely its representation right now?

That question has a precise answer once you're willing to build the smallest possible substrate that can ask it: a graph of atoms and pairs, a small set of rewrite rules, and an equivalence relation that decides when two differently-shaped graphs describe the same thing. Push that far enough and it turns out arithmetic, text, bytecode, tensors, and even a program that reproduces its own source are all instances of one recurring construction — a quotient by observational equality, factored through a single invariant layer that every admissible representation must pass through.

The pages that follow are not an argument for that claim. They are a sequence of small, checkable computations — one per setting — where you can watch the invariant survive a change in representation with your own input, not someone else's example. By the time you reach the end, the "big theorem" will not feel like a leap. It will feel like a name for something you have already made happen seven times.

Start with the thing you already trust

Don't take this on faith — check it. Open any file, compress it, rename it, move it to another folder. Nothing about "what it is" changed, even though every byte on disk did.

what you already know

Copying, zipping, or renaming a file doesn't change its content.

real-life example

A ZIP of a photo and the unzipped photo open to the identical image, pixel for pixel.

formal result

Representation and object are different things. Two representations denote the same object exactly when they decode to the same invariant.

Units: the invariant you already believe in

Before touching files or programs, look at something you settled a long time ago: a distance doesn't change size when you change the ruler you measure it with.

what you already know

5 kilometers and 5000 meters are not two different distances.

real-life example

A road sign in miles and the same road measured in kilometers describe one road.

formal result

A quantity is an equivalence class of (number, unit) pairs under the conversion relation — the number alone is not the object.

Tensors: one geometric storage, many surfaces

Instead of a pair graph, store the same structure as a sparse rank-4 tensor U[i,s,a,r] — one coordinate system for state, selection, action, and result. Text, arithmetic, and machine code all become slices of the same tensor.

what you already know

A spreadsheet cell and a database row can store the same number.

real-life example

An image is a tensor of pixel values; a sound clip is a tensor of amplitude samples — different content, same coordinate-indexed container.

formal result

A sparse tensor is just a relation: U[i,s,a,r] = value is a row (i,s,a,r,value), so storage, joins, and self-application over it are ordinary relational operations.

Self-hosting: closure, not a party trick

Here is an actual quine, not a description of one: a byte string is written into a table on its own diagonal, the table is joined against itself, and the output is checked byte-for-byte against the input. Nothing is hardcoded — edit the text and watch the check run again.

what you already know

Reproducing something exactly, from its own description, feels like a trick.

real-life example

A compiler that can compile its own source code — GCC compiling GCC — is judged correct only if the output is bit-identical across the bootstrap.

formal result

Self-application is real closure only when embed then extract is the identity on the system's own rules: extract(embed(r)) = r.

Closing statement

Nothing here required inventing a framework — each page just checked, computationally, that some quantity survives a change in representation. Stack all seven checks together and the invariant layer isn't a new claim anymore; it's the name for the thing you kept computing.

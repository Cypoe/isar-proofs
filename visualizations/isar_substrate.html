What is the ISAR substrate?

A minimal universal execution substrate derived from a single axiom: something exists and can describe itself. Everything — storage, compute, diff, merge, serialisation — is derived from four invariant carriers.

C_I — Invariant identity

Stable opaque integer IDs. Never reassigned, never meaningful. The thing everything serialises against. Analogous to Unicode code points.

C_R — Rewrite / forward map

The non-invertible map f: ID → Value — normalisation under rules. This is the only "compute" primitive. Codec, encoding, and GPU contraction are all just different shapes of C_R.

C_A — Adjacency

The edge relation: (car_id, cdr_id). Structure without value. The layer you diff, merge, and ship. Never changes during hot compute.

C_S — State / label / display

Human-readable presentation. Separate column, separate table. Never load-bearing. Changing a label costs one cell update and breaks zero references.

The three tables

kernel — 4×4 axiomatic matrices (ISAR), ~256 bytes, boot-only.
node/IOB — relational graph, C_A, durable ACID store.
utensor — sparse COO, C_R/C_S, GPU-hot slab.

Why not Postgres?

Postgres excels at durable relational queries (IOB layer). But parallel reductions need the U-tensor as a GPU-resident sparse slab — SQL joins are sequential and index-bound. The two tiers are separated by access pattern, not preference.

The encoding scheme — ASCII as partial proof

ASCII survived 60+ years because it accidentally separated C_I (integer 0–127) from C_S (glyph rendering). It failed wherever it collapsed them — mojibake is what happens when you apply the wrong C_R to another codec's C_I. Unicode is the partial repair. ISAR is the full repair.

✓ ASCII C_I: integers never moved
✓ backward-compatible extensions
✓ codecs are swappable
✗ C_S baked into the standard
✗ no C_R (no normalisation)
✗ no C_A (no relational structure)

Binary encoding of the kernel

Each matrix is stored as 16 bits (one bit per cell, row-major). The full kernel is 4×16 = 64 bits = 8 bytes plus a 32-bit hash. That is the entire axiomatic substrate — fits in a single cache line.

Scaling behaviour

Sparse tensor contraction over k nonzero entries is O(k) in a single pass. For a tensor with n addressable positions and sparsity factor ρ, k = ρn. In the limit where each position is addressed by an index that is itself a log₂(n)-bit integer, the cost of reading any single coordinate is O(log₂ n) — the information-theoretic lower bound for indexing into an n-element space. Sparse delta encoding exploits this: a delta over d changed entries costs O(d·log₂ n) bits, not O(n·log₂ v).

Sparse delta encoding — theory and demo

The key claim: diff = sparse subtraction on the index space. A delta between two tensor states T₀ and T₁ is the set of coordinate positions where the values differ. Because positions are encoded as log₂(n)-bit integers, the delta is provably the most compact possible representation of the change.

Why positional encoding de-duplicates naturally

In the COO format, each position (i,s,a,r) appears at most once by the primary key constraint. Two separate subgraphs that both contain node 42 with the same value share one entry — union of the COO tables is automatic structural deduplication, no hash comparison needed. Conflicts arise only when the same coordinate has a different value — and those are exactly the semantically meaningful changes that need resolving.

Binary .plex transfer format

A detached subgraph ships as a minimal binary blob: kernel hash (32 bytes) + COO coordinate list + label table. The recipient validates the kernel hash against their local ISAR constants — if it matches, the subgraph slots directly in. No schema negotiation.

O(log₂ n) bound — formal sketch

Let n be the number of addressable positions in the index space (e.g. 2³² for a 32-bit coordinate axis). Any single coordinate is a log₂(n)-bit address. A sparse delta of d changed positions requires exactly d · (log₂(n) + b) bits, where b is the value width. The information-theoretic lower bound for encoding any change distinguishable from the null-change is Ω(log₂ n) per coordinate — so sparse delta encoding achieves the bound. Dense encoding costs n · b regardless of sparsity — exponentially worse for small-d changes.
